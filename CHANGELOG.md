## Unreleased

- added: a live jq query, through gojq v0.12.19 (`github.com/itchyny/gojq`, pure Go, MIT; a new dependency). The structure pane's first row is the query line; the data pane shows the query's results as it changes, off the loop (a 150 ms pause, one job slot: a newer run cancels the older, a late answer is dropped). A path query runs as `path(Q)` and shows the document's own nodes (key order, exact paths); a query that builds values shows gojq's output, the breadcrumb noting `keys sorted by jq` (or `not in document order` where gojq iterated an object's keys sorted). Errors keep the last good results, underline their column and show a caret line; the empty query is the document. It runs on the shown document (edited, or the original after `T`). Value edits are not available while results show. New verbs `jq.set {query}`, `jq.clear`, `jq.yank`, `jq.state`; setting `query.line` (default on).
- changed: `/` is `jq.focus` (new): it focuses the query line (no stop of `tab`'s ring) in insert; `esc` and `enter` (`jq.leave`) go back where `/` came from, the query kept. `viewer.search` stays a verb, with its `/` row after `jq.focus`'s: it answers when `query.line` is off. In the line `ctrl+v` starts a visual selection (it was free in insert) and `[` `{` `(` wrap it (`jq.wrap`); `ctrl+f` (`jq.function`; it moved the cursor right, as the arrow still does) picks a builtin, `tab` (`jq.next-slot`) selects the next empty slot (in that line only; tab opens no completion there).
- added: query mode on the structure pane (`m`, `jq.mode {to}`; `m` was free on every row the viewer answers to): a mode named `query` whose rows on the `node` and `shape` nouns are jq's characters: `.` `jq.path`, `|` `jq.pipe`, `]` `jq.close` / `jq.iterate`, `}` `)` `jq.close`, `[` `{` `(` `jq.open`, `,` `jq.comma`, `a` `jq.anchor`, `backspace` `jq.erase`, `u` / `ctrl+r` `jq.undo` / `jq.redo`, `ctrl+f` `jq.function`, `m` / `esc` back. The list, outline-row, viewer and app tables extend normal in it; the outline's folds (`h` `l`) are copied; the edit keys are not there.
- added: function slots: a builtin from the picker is written with an empty slot (`□`) per argument; the query does not run while one is left.
- added: `o-json query [--compact] FILE|- QUERY` prints each result as JSON, as jq does (`TestQueryCLIAgreesWithJQ` against jq 1.8 where it is on PATH).

- added: `o-json export FILE|- [--map SPEC] [--of PATH] [--format csv|tsv|jsonl|md] [--columns A,B] [--arrays join|json|rows] [--join SEP] [--null empty|null] [--jq] [--out PATH [--overwrite]]` writes one array of the (restructured) document as a table: one row per item (a value that is not an array: one row, column `value`), the item's fields in structure order, nested objects as dotted columns (`owner.name`), arrays in a cell joined (`;`), as JSON, or one row per item; a missing field and `null` are empty cells (`--null null` writes `null`). `--jq` prints a jq program whose `jq -r` output is the same csv or tsv, record by record. Formats are rows of one table (`exportFormats`: extension, writer, jq step).
- added: `w` (`restructure.write`, `viewer.write`) to a `.csv`, `.tsv`, `.jsonl` or `.md` path writes the export of the array under the cursor (the selected array's items, else the nearest array holding the selection, else the data pane's table) instead of JSON, with the same overwrite rules; an export leaves the edits unsaved. Any other extension is JSON, as before.
- added: `viewer.export {path, format, of, columns}` (args form for the path) and its confirm `viewer.export-overwrite`; no default key (palette, CLI, `bindings.json`). `restructure.jq {format, of, columns}` (new parameters) ends the program in the export's `@csv` / `@tsv` step.
- added: settings `export.arrays` (`join` default, `json`, `rows`), `export.join` (default `;`), `export.null` (`empty` default, `null`).
- added: value edits in the viewer's data pane, a second layer of **value patches** applied after the restructure (structure edits stay shape-level). In the edited view: `r` / `i` (`value.edit {text, select}`) edit a value in an inline input, its text selected (`rename.select`); `enter` or `esc` sets it, the type read from the text (number, `true`/`false`, `null`, JSON object or array, `"…"` forces a string, else the text as a string; the input's prefix shows the type). `d d` (`value.delete`) deletes a field or item; `o` (`value.add {key, text}`) adds a key (name with the `restructure.new-key` placeholder selected, then the value, `null` selected) or an item after this one; `K` (`value.rename {key}`) renames a key in that one object; `p` (`value.paste`) puts the register's value over this one. In a table the value is the cell under the cursor (`#`: the row; a missing cell is added). New verbs `value.yank`, `value.patches` (the list, `orphaned: true` marked), `value.drop {index}`, `value-input.accept` / `cancel`. Each edit is one undo step on the restructure's stack; `u` / `ctrl+r` (new rows on the viewer) undo from the data pane. `[+]`, `q`, `e`, `R`, `p` and `viewer.new` count them as unsaved; the breadcrumb reads `N value edits (K orphaned)`. `r`, `i`, `d d`, `o`, `u`, `ctrl+r` were free on the data pane's rows; `K` shadows the framework's guarded `ochazuke.detail.scroll` there only where `value.rename` is available; `p` is `value.paste` in the edited data pane and passes on to `viewer.paste` where it is not available.
- added: setting `data.editable` (default on); off keeps the data pane read-only.
- added: the mapping spec's `"patches": [{"op": "set"|"delete"|"add"|"rename", "path", "value", "key", "after"}]`, read by `o-json restructure --map`, kept by `--mapping` (one per line) and appended by `--jq` as guarded `setpath` / `delpaths` steps, so the program's output equals the Go result. The orphan rule: a patch applies only where its target is there (every step of the path; for `add`, the container without that key or an index at most its length; a `rename` onto a key the object has is not there); otherwise it is kept and skipped, never an error, and applies again once its path is back.
- changed: `y` on a table row copies the cell under the cursor on a field column (the row on `#`, as before); a yanked value keeps its type in the register (`o-json.value:KIND`), so `p` puts `"42"` back as a string. The data pane keeps its selected row and column when the same path is shown again (after an edit or an undo).
- changed: `q` and `ctrl+c` (`app.quit`) with edits no write saved ask once, as vim refuses `:q`: "Quit without writing? The edits no write saved are lost." (`viewer.quit`, new, a confirming verb); `y` quits, `n` stays. `app.quit {force: true}` quits without asking; `Q` (new, on the viewer and the restructure page; it was free there) runs it, as vim's `:q!`. A write clears the unsaved state. o-json wraps the framework's `app.quit`, so every key and caller of it asks the same way.
- changed: `p` (`viewer.paste`) with edits no write saved asks once first (`viewer.discard {paste, text}`, new parameters), as `e` and `R` do.
- added: the viewer's structure pane is the restructure editor, edited in place. A document opens with it a copy of its shape (`Structure · edited`): every shape a node mapped to itself, so the output is the input (a shape whose values mix types, or an object of more than 200 keys, is one node that copies its values). Every key of the restructured tree works there directly (`d d`, `y y`, `p`, `P`, `> >`, `g >`, `> j`, `> k`, `< <`, `S`, `t`, `r`, `o`/`O`/`a`, `V` selections, `u`/`ctrl+r`); each node keeps its origin (`from`). The data pane shows the restructured document live and the focused node's restructured value. Nothing is written until `w`: in the edited view `w` / `W` are `restructure.write` with its rules (a new file, an existing one asks, the source never; `W` the source after one confirm). The breadcrumb reads `FILE [+]` and the pane `Structure · edited [+]` while edits are unsaved.
- added: `T` (`restructure.show`, now also in the viewer; `side` takes `edited` as `restructured`) flips the structure pane and the data pane between the original and the edited document, on the same shape; from the data pane the focus stays there. `T` was free on every row the viewer answers to. On the original, `/`, `n`, `N`, `t`, `esc` (filters, now available only there), `p` (paste), `w` (`viewer.write`) and `s` work as before.
- added: setting `structure.editable` (default on); off keeps the viewer read-only, as it was, and the restructure page alone edits.
- changed: the viewer and the restructure page share one restructure state (one tree, lent to the page that is open). `M` with in-place edits opens on them; with none it starts empty as one undo step, and back in the viewer with nothing sent the copy returns. `M` opens the original at the shape of the viewer's selected node.
- changed: `viewer.open` (`e`) and `viewer.load` (`R`) ask once with edits no write saved: `viewer.discard {path}` (new parameter) drops them and reads the file; `viewer.new` asks through it as before. The confirm reads "The restructure has edits no write saved. Drop them?". Opening a document is one undo step on the restructure state, so `u` brings dropped edits back.
- added: yank, delete and put on the restructured tree, through ochazuke's registers. `y y` (`node.yank`, new) yanks a node with its children; `d d` (`node.delete`, kept) now deletes into the register too; `"a` picks register a. `p` / `P` (`node.put {before}`, new) put at the level where they land: next / previous sibling on a plain key, first child / previous sibling on an expanded object or array, next sibling after the whole object / previous sibling on a collapsed one, and the first key on the root for both. Delete then put is a move (the nodes keep their ids, `from` and children); yank then put is a copy (new ids, the same shapes mapped again). A key landing beside a sibling of its name is numbered (`a-2`), as placeholders are. A put whose mapping would not check (into an array item) is refused with a notice. Over a `V` selection, `d` and `y` (`restructure.delete`, `restructure.yank`, new) act on every selected node as one undo step; `d d` and `y y` are not available while a selection is on (it was `V` … `d d`). A register holds the nodes as `o-json.nodes` JSON text, so `"A` appends and the numbered registers work. `p`, `P` and `y y` were free on every row the tree answers to; `y` alone (the list's row yank) now waits for the sequence timeout on the restructured tree.
- changed: the restructured tree uses vim's keys for nesting. `> >` (`node.indent {into: previous}`) nests a node into the nearest sibling above that takes keys, as its last key, and `g >` (`{into: next}`, new) into the nearest below, as its first; plain siblings between are skipped and the cursor follows. `> j` / `> k` (`{with: next|previous}`, new) nest this node and the one below / above. `< <` is `node.dedent`, `S` is `node.wrap` (was the fallback of `>`). Alone, `>` and `<` are prefixes bound to `ochazuke.key.ignore` there (the badge reads `NORMAL >`), so they never fall through to the divider; `V` marks with `> >` / `< <` act on every marked node as one undo step. `S` was free on every row the tree answers to.
- added: `ctrl+w >`, `ctrl+w <`, `ctrl+w =` move and reset the divider on every page (counts work: `3 ctrl+w >`); the pane verbs are available only while the page draws a split. `>` `<` `=` still resize on the original tree and in the viewer.
- changed: `< <` moves the node, with its children, just before its old parent (it went after the parent's subtree); repeats stack before the parent in order. Out of an array item the collected key lands just before the array's key.
- fixed: dedenting the last child made its parent copy its original value again (`{"a":1,"x":{"b":2,"c":3},"b":2,"c":3}`). A node that was built from children (`nodeMeta.built`) and has none left is written as an empty object (a wrapper); its origin stays in the `from` column and for undo.
- fixed: wrapping a node beside a sibling named `x` was not available (the availability probe wrapped with the key `x`); the probe now uses the placeholder the wrap gives.
- changed: each `node/normal` row has its own hint (`> > nest`, `g > nest below`, `> j nest +next`, `> k nest +previous`, `< < out`, `S wrap`, `t array`, `t object`), so a hint shows whenever its row would answer; the lone `>`/`<` rows read `prefix` in `?`.
- added: `t` on a root holding keys makes the document an array of itself, `[ {keys} ]` (`{"from": ".", "to": ".[]"}`), and `t` turns it back; an array document's own array becomes `{"new-key": [...]}` with the placeholder opened selected. `node.object`'s description says why `t` does nothing on an array whose item has many values.
- added: an empty document, like vim's empty buffer. `o-json` with no file (and stdin a terminal) opens the viewer on `[no file]` instead of failing with "a file is required"; the breadcrumb names the keys that fill it. `viewer.new` empties the viewer from inside, asking first (new verb `viewer.discard`) when the restructure page has edits no write or export-map saved; the reset is one undo step on the restructure page.
- added: `e` (`viewer.open {path}`, required, so the args form asks) opens another file off the loop. The path field is free text with suggestions from `viewer.files`: the recent files, newest first, then the files in the current file's folder. `viewer.load` stays the reload (`R`); it is available only when there is a file. The TUI's first read is `viewer.open`.
- added: recent files: each file opened is recorded in the state directory's `recent.json`, newest first; new setting `recent.size` (default 10), files that are gone dropped; `viewer.recent` lists them.
- added: `p` (`viewer.paste {text}`) parses the system clipboard (pbpaste, wl-paste, xclip, xsel) into the buffer as a document of no file; invalid JSON is an error with its line and column. The restructure page works on it.
- added: `w` (`viewer.write {path}`, args form) writes the shown document to a new file; an existing file asks (`viewer.overwrite`), the source is refused, and a document of no file takes the written path. `e`, `p` and `w` were free on every row the viewer answers to (the tree, its outline and list, the data panel's item, field and line rows, rows, viewer, app).

- added: the restructured tree shows the document itself as its first node, `. (root)`, an object or an array, present on the empty tree too. It is an ordinary node: `d d`, `r`, `<` and wrapping are not available on it (the keys pass on; the outline's own `d d` row is unbound so `node.delete` answers), and nothing goes beside it (`o` adds its first key, `O` is refused). `t` on the empty root makes the document an array whose `[]` item takes the first shape sent (`s` on `.items[]` maps `.items[]` to `.[]`, the items become the top level); on a root holding one array key it lifts that array to the root, and on an array root it puts the array back under its key. Undo and redo cover each flip; the Mapping panel, `--mapping` and `--jq` follow.
- added: `W` (`restructure.write {path, force: true}`) replaces an existing file without asking, and writes the source after one confirm (new verb `restructure.overwrite-source`, "Overwrite the source PATH with the restructured document?"), as `restructure --out SOURCE --overwrite` does. `w` is unchanged: it refuses the source and asks before replacing another file. `W` was free on every row the page answers to.
- changed: the page's mapping writes every `to` path with a leading dot (`.[]`, `.["new-key"]`, as jq writes them); it wrote `["new-key"]`.
- added: `L` on the restructure page flips the layout (`restructure.layout`, split / single), keeping the focused tree; the footer hints it and the breadcrumb reads `split layout (L: single)`. `L` was free on every row the page answers to.
- changed: the restructure page opens focused on the original, on the shape the viewer has selected (else the first), however it opens and every time; in the single layout it opens showing the original. It used to come back to the last focus, the restructured tree included.
- added: on the restructure page, `>` where a node cannot nest (the node above is a plain value, or there is none) wraps it in a new object (`node.wrap {key}`), and `o`/`O`/`a` (`restructure.add-key {where, key}`) add an empty object key below, above or inside. Every new key opens with a placeholder selected (ochazuke's select mode): typing names it, `esc` or a motion keeps it. The placeholder is the new setting `restructure.new-key` (default `new-key`), numbered past its siblings' keys. A wrapper has no `from`; making it is one undo step. `>` on an array's `[]` item still resizes the divider.
- added: `t` (`node.array`, `node.object`) turns a key into an array of itself and back, only where the mapping still checks.
- added: selecting a node on the restructured tree marks the shape it comes from on the original, and selecting a shape marks where it went (the `marker.queued` tone, the accent foreground).

- added: the restructure page (`M`, `restructure.open`). It is an editable tree over shapes that starts empty: `s` (`shape.send`, also from the viewer's tree, over a `V` selection, and `restructure.add {path}`) sends a shape with the ancestors it needs and its fields. Every node keeps its origin. `>`/`<` (`node.indent`, `node.dedent`) nest and move out by the JSON rules, given as availability, so where they cannot apply the key resizes the divider; `<` out of an array item collects the values into an array. `r` (`node.rename {key}`) and `d d` (`node.delete`) rename and delete, and `u`/`ctrl+r` undo and redo. The page's state is a mapping, shown live in the `--mapping` form and runnable: `w` (`restructure.write {path}`, args form) writes a new file, asks before replacing an existing one (`restructure.overwrite`) and never writes the source; `restructure.jq` copies the program and `restructure.export-map {path}` writes the mapping. Other verbs: `restructure.close`, `show`, `undo`, `redo`, `mapping`, `layout`. New setting `restructure.layout` (`split`, the default, puts the original beside the restructured tree; `single` shows one, and `tab` swaps them). The outline's `tab`, `shift+tab` and `i` are unbound, so nesting goes through the JSON rules and renaming through `r`.
- changed: `restructure --mapping` prints one entry per line.
- changed: a repeated key reads as jq reads it everywhere: the last value, at the first key's position. The viewer's tree, tables and fields, `get`, `table`, `structure` and `restructure` all show `33` for `{"id": 3, "id": 33}` (they showed `3`, while jq and `restructure` gave `33`). The field keeps its error tone and its breadcrumb note `duplicate key "id" (2): jq keeps the last`.
- changed: requires ochazuke `v0.38.0` (was `v0.31.0`). The key rows moved from Go `Bind` chains into an embedded `bindings.json` in the one-row-per-line format (same rows, same order); the rows tables' cell keys lost their `table-cells` row guards, since those list verbs are available only on a cell table. `TestNoDeprecatedOchazuke` runs ochazuke's strict check.
- added: `o-json restructure FILE --map SPEC.json [--jq | --mapping] [--out PATH [--overwrite]]`. A mapping of shape paths (`{"map": [{"from", "to"}]}`; no `from` makes a wrapper, `"to": null` drops) is applied in Go keeping key order, or printed as a jq program that never fails on an optional or mixed-type shape, or printed complete with every left-out shape as a drop. Output goes to stdout or, with `--out`, to a new file written atomically; an existing file, the source among them, is replaced only with `--overwrite`. o-json now writes files, but never the source by default (`TestReadOnlyNeverWrites` is now `TestViewerNeverWritesTheSource`).
- fixed: a key an object repeats counts once for that object, so a field no longer reads `4/3` and a repeat no longer hides an optional field (`[{"id":1,"id":11},{"id":2},{"name":"x"}]`: `id` is `2/3`, optional). The shape records `duplicates: {objects, most}` (also in `structure --format json`), the structure notes `duplicate key (N)`, and the viewer tones the field's name with the error role and says `duplicate key "id" (2): jq keeps the last` on the breadcrumb.
